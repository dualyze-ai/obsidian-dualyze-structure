# Aliceが5,000行のAWSノートを構造化された知識ベースに変えた話

Aliceには `AWSガイド.md` というノートがある。

最初はちょっとしたメモとして作った。18ヶ月後、Lambda・API Gateway・DynamoDB・SAM・IAMなどを書き続けた結果、5,000行を超えていた。

もうどこに何があるか分からない。

BobがDualyze Structureを紹介する。

---

## 問題：全部入りのノートは使えなくなる

---

**Alice：**
AWSのメモ、ずっと1つのノートに書き続けてたんだけど、もう手に負えなくて。

**Bob：**
どれくらいある？

**Alice：**
5,000行くらい。DynamoDBで検索すると、同じファイルの中で40件ヒットする。

**Bob：**
それが問題。200行なら1つのノートで機能する。5,000行になると「情報の墓場」になる。入れた情報が出てこない。

**Alice：**
自分で分割しようと思ったこともあったけど、セクションが30個くらいあって、手でやったら何時間もかかる。

**Bob：**
ノートを右クリックして「Create Structure」を選んでみて。

---

## ステップ1：生成されるファイルを確認する

---

**Alice：**
ダイアログが開いた。検出されたセクションのリストが出てる：

```
導入
Lambda
API Gateway
DynamoDB
SAM
ネットワーク
IAM
CloudWatch
...
```

11セクション。下に「スプリットノート11件 ＋ インデックス1件 ＋ MOC1件を作成します」って書いてある。

**Bob：**
「Create」を押すまで何も書き込まれない。これが確認ステップ。

**Alice：**
自分で書いた`##`見出しが全部検出されてる。

**Bob：**
`##`（H2）見出しが1ノートになる。`###`以下の子見出しはその中に収まったまま分割されない。

**Alice：**
じゃあ `## Lambda` の中に `### コールドスタート`、`### レイヤー`、`### 同時実行数` って書いてあっても、全部 `Lambda.md` に入るってこと？

**Bob：**
そう。

> **💡 Structure Splitとは**
> Dualyze Structureはノート内の `##`（H2）見出しを読み取り、見出しごとに独立したファイルを生成します。`###`以下の子見出しは親ファイルの中に収まります。元のノートは削除されず、リンクの一覧（Structure Index）に書き換えられます。

---

## ステップ2：実行する

---

**Alice：**
「Create」を押した。一瞬で終わった。何が起きたの？

**Bob：**
ファイルエクスプローラーを見てみて。

**Alice：**
`AWSガイド/` というフォルダができてて、中に：

```
AWSガイド - 導入.md
AWSガイド - Lambda.md
AWSガイド - API Gateway.md
AWSガイド - DynamoDB.md
AWSガイド - SAM.md
...
AWSガイド.md          ← 元のノート（書き換え済み）
AWSガイド MOC.md      ← 新規生成
```

**Bob：**
元の `AWSガイド.md` を開いてみて。

**Alice：**
リンクの一覧になってる：

```markdown
# AWSガイド

## Structure

- [[AWSガイド - 導入]]
- [[AWSガイド - Lambda]]
- [[AWSガイド - API Gateway]]
- [[AWSガイド - DynamoDB]]
- [[AWSガイド - SAM]]
...
```

**Bob：**
それが Structure Index。ここからワンクリックでどのセクションにも飛べる。

**Alice：**
分割後のノートを開くと、frontmatterに `parent: "[[AWSガイド]]"` って入ってる。親ノートへのバックリンクも自動でできてるんだ。

---

## ステップ3：MOCとKnowledge Map

---

**Alice：**
`AWSガイド MOC.md` を開いた。Mermaidのフローチャートがある。

**Bob：**
それがKnowledge Map。全スプリットノードが親ノードに接続された形で視覚化されてる。

**Alice：**
Lambda、DynamoDB、SAM…11個のセクションが全部つながって見える。これ、ひと目で全体の構造が分かる。

**Bob：**
それが「巨大なノート」と「知識ベース」の違い。片方はドキュメント。もう片方は探索できる構造。

**Alice：**
しかもこれを手でやらなくていい。

> **💡 MOCとは**
> MOC（Map of Content）はスプリットノートと同時に自動生成される目次ノートです。全関連ノートの一覧と、Mermaidフローチャートによる視覚的なKnowledge Mapが含まれます。トピック全体の俯瞰図として機能します。

---

## 変換の全体像

```text
AWSガイド.md（5,000行、1ファイル）
        ↓
  Create Structure
        ↓
AWSガイド - 導入.md
AWSガイド - Lambda.md
AWSガイド - API Gateway.md
AWSガイド - DynamoDB.md
AWSガイド - SAM.md
...
        ＋
AWSガイド.md         （Structure Index — ナビゲーションのハブ）
AWSガイド MOC.md     （Knowledge Map ＋ 全ノートの一覧）
```

## おわりに

---

**Alice：**
1年以上ずっと1ファイルに書き続けてた。分割するのが怖かったから。でもこれ、3秒で終わった。

**Bob：**
分割が怖い理由は大抵「全体像を失いたくない」から。Structure IndexとMOCがそれを解決してくれる。全体像を保ちながら、各セクションが独立して検索できるようになる。

**Alice：**
前は「DynamoDB」で検索すると、同じファイルの中でノイズだらけだった。今は `AWSガイド - DynamoDB.md` の1件だけ返ってくる。

**Bob：**
それが構造化の本質。バラバラにすることじゃなくて、見つけやすくすること。

**Alice：**
分割すると全体像を失うと思ってた。

でも逆だった。Structure IndexとMOCが全体像を保ってくれる。分割されたノートが、各セクションを初めて「使えるもの」にする。

**Alice：**
Reactのガイドはもっと長い。次はそれでやってみる。
